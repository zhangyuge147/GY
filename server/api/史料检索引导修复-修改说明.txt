史料检索引导修复-修改说明（L46，2026-10-29 凌晨）
====================================================

一、修改原因
----------
用户实测反馈：智能问答（/api/chat）回答"江姐"后建议"到平台的「史料检索」
页查证权威出处"，但用户去史料检索页查不到江姐——引导与收录不同步。

排查还原的完整时间线（三层叠加）：
  1. 江姐语料 2026-10-28 22:57 已入库（corpus\江竹筠.txt，第七轮收录，
     人物名单 8 条出处已核验），23:00:11 索引已重建（含江姐）；
  2. 但当时 server 进程为 20:22 启动的旧实例——server/api/rag.py 的
     _RUNTIME 进程内缓存着旧索引（懒加载一次不刷新），内存里没有江姐
     → 用户测试期间史料检索确实查不到。23:44 重启 server（L45 修复时）
     后索引重新加载，此问题已消失；
  3. 00:18 用户实测时 rag 后端实际已命中江姐语料（日志 200），但彼时
     api.deepseek.com 出现 SSL 偶发失败，旧兜底文案"（DeepSeek 未配置，
     仅展示检索到的史料）"误导性强，用户观感为"没有"；
  4. 剩下的真代码缺陷：chat.py 的 GENERAL_SYSTEM 让 LLM 无差别建议
     "到史料检索页查证"——LLM 不知道平台收录情况，问未收录人物（如
     向秀丽）时引导永远指向查不到的页面（死链）。

二、修改内容（本目录 2 个文件）
----------
1. api/chat.py：
   - 删除模块级常量 GENERAL_SYSTEM，改为 _general_system() 函数 +
     _corpus_roster() 辅助：实时读盘 corpus 目录文件名（无缓存），把
     史料检索页收录人物名单注入系统提示词；
   - 引导规则从"无差别指向史料检索页"改为分情况：名单内人物 → 建议
     到「史料检索」页查证；名单外人物 → 建议以人民网、共产党员网等
     权威党史资料为准，不指向平台「史料检索」页；
   - 实时读盘的意义：知识库语料更新后无需重启 server，引导名单即随
     最新收录变化（对比 rag 接口的 _RUNTIME 索引缓存——那个更新后
     必须重启）；
   - _system_prompt(persona) 中 GENERAL_SYSTEM 引用同步改为
     _general_system()。英雄人设分支（_hero_system）只对收录英雄生效，
     无此问题，不动。

2. api/rag.py：
   - DeepSeek 生成失败的兜底文案由"（DeepSeek 未配置，仅展示检索到的
     史料）"改为"（DeepSeek 调用失败或未配置，仅展示检索到的史料）"
     ——实际失败原因多为 api.deepseek.com 偶发网络异常（SSL/超时），
     旧文案误导用户以为配置坏了。

三、验证
----------
1. py_compile 两文件通过；server 已重启部署（uvicorn 后台进程）；
2. 史料检索命中复测：POST /api/rag/ask {"question":"江姐"} → 命中
   3 条江竹筠语料（score 0.67/0.63/0.61，均过 0.5 知识库阈值，非联网
   兜底），"江姐是谁"同样命中——用户网页端史料检索已可查到江姐；
3. 系统提示词产物验证（不依赖 LLM 网络）：_general_system() 输出含
   20 人收录名单（江竹筠在列、向秀丽不在列），分情况引导规则完整；
4. chat 的 LLM 端到端输出验证：因 api.deepseek.com 当时持续 SSL 失败
   （6 次重试全挂，服务端日志可见网络异常）暂无法完成，属网络环境
   问题非代码问题——网络恢复后 LLM 将按新提示词引导，前端会显示
   chat.py yield 的 {"error": "网络异常…"} 提示。
5. 临时诊断脚本（_diag_chat_guide_test.py）已删除（_diag 残留 0）。

四、已知边界
----------
1. DeepSeek API 偶发 SSL/网络失败期间，智能问答与史料检索的"答案生
   成"降级，但史料检索的命中列表照常返回（by design）；演示前建议
   先 curl 一次确认网络；
2. chat 的名单注入读的是 corpus 文件名（人名 = 文件名 stem），若语料
   文件命名与人物常用称呼不一致（如"江竹筠.txt"而用户问"江姐"），
   名单中显示的是文件名——LLM 拿到名单后可自行对应（江竹筠=江姐），
   一般场景无碍；后续若收录人数增长明显，可改为人物名单.csv 的
   "常用称呼"字段注入（二期）；
3. 部署注意（防复发，与 L45 教训同源）：
   - 改 server/api 代码后必须重启 uvicorn；
   - **知识库语料更新/重建索引后同样必须重启 server**——
     server/api/rag.py 的 _RUNTIME 索引是进程内缓存，不重启永远
     用旧索引（本次"史料检索查不到江姐"的直接原因）。

五、影响范围
----------
仅 /api/chat 的系统提示词与 /api/rag/ask 的一条兜底文案；路由、
接口签名、前端零改动。相关注册见 restoration\局限与精修清单.txt【L46】。
